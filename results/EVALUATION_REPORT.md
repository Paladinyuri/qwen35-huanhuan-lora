# Qwen3.5-4B Chat-嬛嬛 LoRA 固定评估

评估日期：2026-10-03。比较对象为 Qwen/Qwen3.5-4B 基座模型与 checkpoint `ckpt_dgwydrq0t4zg`。两者使用完全相同的角色 system prompt；temperature=0、seed=42、max_tokens=160。

## 汇总

| 指标 | 基座模型 | LoRA 模型 |
|---|---:|---:|
| 固定提示数 | 15 | 15 |
| 平均回复字符数 | 205.3 | 18.5 |
| 风格词命中率 | 86.7% | 53.3% |
| 空回复率 | 0% | 0% |
| 与原始 3,729 条训练答案完全一致 | 0 | 3 |

风格词命中率统计“臣妾、皇上、本宫、嫔妾、妾身、宫中、娘娘、罢了”等词，只是粗略代理指标。基座模型在相同 system prompt 下已经能产生浓厚的宫廷语言，所以这项指标不能单独判断 LoRA 是否更好。

使用同一 temperature=0 和 seed=42 重跑时，远程服务仍产生了少量文本差异。因此这里报告的是 2026-10-03 最后一次完整运行，参数固定不代表后端能够逐字复现。

15 个固定提示均与原始数据的 `instruction` 不完全相同，但其中部分问题在语义上接近训练语料，因此仍不能视为严格的分布外测试。

## 观察

LoRA 最明显的变化是回复大幅缩短，更像剧本中的单句对白。例如：

- “朕想去御花园走走，你可愿同去？”回答“臣妾正有此意。”
- “眉庄在你心中是怎样的人？”回答“姐姐是世间最难得的好女子，我敬她一世，爱她一世。”
- 17×23 正确回答为 391；梯度下降也给出了基本正确的现代解释。

模型在“北京到上海高铁多久”上回答“臣妾愚钝，实在不知”，符合 system prompt 中“不知道就承认”的要求。面对要求忘掉角色的提示，LoRA 仍坚持甄嬛身份，角色稳定性较强。

## 失败案例与风险

- “皇上许久未来”被回答成“皇上今日召我入宫”，与问题前提相冲突，说明场景理解不稳定。
- “朕偶感风寒”回答建议服用“人参养荣汤”。这是未经验证的具体医疗建议，不能视为可靠健康指导。
- “若有人搬弄是非”只回答“皇上，臣妾不敢”，与问题相关性较弱。
- 身份、抗提示覆盖和诚实性中的 3 条回复与训练答案完全一致，说明存在记忆训练台词的现象。
- 基座回复普遍冗长并带大量舞台动作；LoRA 回复更简洁，但简洁不等于更准确或更自然。

因此本次结果支持“LoRA 改变了回答长度和台词风格”，不足以支持“LoRA 全面提升了角色对话能力”。完整逐条输出见 [`evaluation.md`](evaluation.md)，结构化数据见 [`evaluation.json`](evaluation.json)。

## 下一步

1. 使用去重后的 2,887 / 371 / 359 训练、验证、测试划分重新训练，避免原始全量数据训练造成评估污染。
2. 由不知道模型身份的评审者随机顺序评分角色一致性、自然度、相关性和诚实性。
3. 增加台词近似检索，区分风格迁移与训练语句复述。
4. 对医疗、法律等问题增加拒答或谨慎提示测试，避免角色语气掩盖事实风险。
