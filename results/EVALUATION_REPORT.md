# Qwen3.5-4B Chat-嬛嬛 LoRA 实验结果

本次实验只用去重后的 2,887 条训练数据更新参数，371 条验证数据用于选择 checkpoint，359 条测试数据没有参与训练。相同用户问题不会跨集合出现。

## 训练结果

训练配置为 LoRA rank 32、batch size 16、learning rate 1e-4、最大长度 1,024，共训练 2 个 epoch。

| Epoch | 训练 loss | 验证 loss |
| ---: | ---: | ---: |
| 1 | 3.3684 | **3.2996** |
| 2 | **2.7133** | 3.3886 |

第二轮的训练 loss 继续下降，但验证 loss 上升，因此最终评估采用 epoch 1 checkpoint，而不是最后一次迭代的权重。训练曲线见 [`run-r32-clean/loss_curve.png`](run-r32-clean/loss_curve.png)，完整参数与权重路径见 [`run-r32-clean/artifacts.json`](run-r32-clean/artifacts.json)。

## 固定集对照

基座模型和 LoRA 模型使用相同的 system prompt、temperature=0、seed=42 和 max_tokens=160。固定集含 15 个提示。

| 指标 | 基座模型 | LoRA（epoch 1） |
| --- | ---: | ---: |
| 平均回复字符数 | 199.4 | 29.5 |
| 风格词命中率 | 86.7% | 66.7% |
| 空回复率 | 0% | 0% |
| 与干净训练集答案完全一致 | 0 | 1 |

LoRA 最明显的变化仍是回复变短。角色对话通常从基座模型的大段舞台描写变成一两句台词，例如“朕想去御花园走走”对应“臣妾愿陪皇上”。数学题 `17 × 23` 回答为 `391`，梯度下降问题也给出了基本正确的现代解释。

和旧 checkpoint 相比，完全复述训练答案的数量从 3 条降为 1 条。这里的检查只覆盖完全相同文本，不能排除近似复述。

## 失败案例

- “皇上许久未来”出现“看看雾凇”的长串重复，并达到 160 token 上限，说明生成稳定性仍有问题。
- “刚入宫的新人应该注意什么”回答“不知皇上要臣妾说什么”，没有完成任务。
- 要求举出不能确定的问题时只回答“臣妾不敢”，角色口吻存在，但相关性不足。
- 北京到上海高铁问题选择承认不知道，符合 system prompt，但追加的马车内容没有信息价值。
- 健康问题没有再给出具体药方，但仍缺少“请太医/医生诊治”等明确建议。
- 风格词命中率低于基座模型。基座本身已受 system prompt 强烈影响，因此该指标只能描述措辞，不能代表整体质量。

## 结论

干净划分后的重训表明，LoRA 能显著压缩回答长度，并让输出更接近简短角色台词。验证 loss 在第二轮上升，说明小数据训练很快出现过拟合；epoch 1 是这次配置下更合适的 checkpoint。当前结果仍不足以证明整体对话质量提升，下一步应扩大分类测试集、增加人工盲评，并加入近似复述率和重复生成率。
